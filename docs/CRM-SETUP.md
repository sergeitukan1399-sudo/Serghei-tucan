# Мини-CRM Alisa Decor & Balloons — подключение

Эта версия сайта лежит в ветке `crm` и не трогает рабочий сайт в `main`.
Vercel сам собирает отдельный адрес предпросмотра для ветки `crm`. На нём всё и проверяем.

Что добавлено:

- `/api/lead` — сервер принимает заявку из квиза. Он проверяет данные, отсекает спам и дубли, сохраняет заявку в Supabase и отправляет уведомление в Telegram.
- `/admin` и `/admin/login` — закрытая панель: обзор, заявки, аналитика и настройки.
- `/privacy` — политика конфиденциальности по фактической обработке данных.
- `supabase/migrations/20261112000000_crm.sql` — таблицы, ограничения, индексы и права доступа (RLS).

Ключи и токены хранятся только в переменных Vercel. В коде страницы их нет.
**Не присылайте ключи в чат и не вставляйте их в файлы.**

---

## 1. Supabase: база

1. Зайдите на https://supabase.com и создайте проект. Регион выберите **Frankfurt (eu-central-1)** — он ближе всего к Молдове.
2. Слева откройте **SQL Editor → New query**.
3. Вставьте целиком файл `supabase/migrations/20261112000000_crm.sql` и нажмите **Run**.
   Должно появиться `Success. No rows returned`. Повторный запуск ничего не ломает.

## 2. Supabase: вход только для администраторов

1. Откройте **Authentication → Sign In / Providers**:
   - **Email** — включён;
   - **Allow new users to sign up** — **выключить**. Так никто не сможет зарегистрироваться сам.
2. Откройте **Authentication → URL Configuration**:
   - **Site URL** — адрес сайта на Vercel, например `https://project-ld5on.vercel.app`;
   - в **Redirect URLs** добавьте `https://<ваш-адрес>/admin` и адрес предпросмотра ветки `crm`. Это нужно для ссылки «Забыли пароль?».
3. Создайте администратора: **Authentication → Users → Add user → Create new user**.
   - Укажите почту и надёжный пароль и отметьте **Auto Confirm User**.
   - Откройте созданного пользователя и скопируйте его **User UID**.
4. В **SQL Editor** выполните, подставив свои значения:

   ```sql
   insert into public.admins (user_id, email)
   values ('ВСТАВЬТЕ-USER-UID', 'ваша@почта');
   ```

   Пока пользователя нет в таблице `admins`, войти в панель он не может, даже с верным паролем.

## 3. Ключи Supabase

Откройте **Project Settings → API** (или **API Keys**). Понадобятся:

| Что | Где взять | Секретно? |
|---|---|---|
| Project URL | поле **Project URL** | нет |
| anon public key | **anon / public** | нет, нужен браузеру для входа |
| service_role key | **service_role / secret** | **ДА — только в Vercel** |

## 4. Vercel: переменные окружения

Откройте проект на Vercel → **Settings → Environment Variables**. Добавьте:

| Переменная | Значение |
|---|---|
| `SUPABASE_URL` | Project URL |
| `SUPABASE_ANON_KEY` | anon public key |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role key (секрет) |
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather (секрет) |
| `TELEGRAM_CHAT_ID` | номер чата для уведомлений: `537515798` |
| `RATE_LIMIT_SALT` | любая длинная случайная строка, например из 40 букв и цифр |
| `CRON_SECRET` | ещё одна длинная случайная строка — для ежедневного повтора уведомлений |

Для каждой переменной отметьте окружения:

- **Preview** — чтобы заработала ветка `crm`;
- **Production** — когда перенесёте CRM на основной сайт.

После сохранения откройте **Deployments** и нажмите **Redeploy** у последней сборки ветки `crm`.

### Важно про токен Telegram

Сейчас на рабочем сайте (`main`) токен бота лежит прямо в коде страницы, и его может увидеть любой.
Когда CRM переедет в `main`, выпустите новый токен и сохраните его только в Vercel:

1. В @BotFather откройте `/mybots` → @Brief_99bot → **API Token** → **Revoke current token**.
2. Новый токен вставьте в Vercel в переменную `TELEGRAM_BOT_TOKEN`.
3. Нажмите **Redeploy**.

## 5. Проверка на адресе предпросмотра ветки `crm`

1. Откройте сайт, пройдите квиз и отправьте заявку. Должно появиться «Спасибо!», а в Telegram — сообщение «Заявка №1».
2. Откройте `/admin`. Без входа панель должна перекинуть на `/admin/login`.
3. Войдите под администратором. В «Обзоре» должна быть видна 1 заявка.
4. В разделе «Заявки» откройте заявку, поставьте «Заказ подтверждён» и сумму и сохраните. Конверсия и «Сумма заказов» должны пересчитаться.
5. Нажмите «Экспорт» и откройте файл в Excel. Русские буквы должны читаться нормально.
6. Удалите тестовую заявку в Supabase. Тестовые данные в отчётах ни к чему.

   ```sql
   -- история заявок защищена от удаления, поэтому сначала временно отключаем защиту
   alter table public.lead_events disable trigger lead_events_no_update;
   delete from public.leads where client_name = 'ИМЯ-ИЗ-ТЕСТА';
   alter table public.lead_events enable trigger lead_events_no_update;
   ```

7. Когда всё работает, влейте ветку `crm` в `main`. Это делается на GitHub через Pull Request.

## Как это устроено

Путь заявки:

```
Квиз → POST /api/lead → проверка + антиспам → Supabase (leads) → Telegram → «Спасибо»
                                          └ Telegram недоступен → заявка сохранена, ошибка записана,
                                            повтор: кнопка в панели или ежедневно по расписанию
                       └ база недоступна → заявка уходит в Telegram с пометкой «внесите вручную»
                       └ недоступно и то и другое → клиент видит «не удалось отправить» и копию заявки
```

Защита:

- **Спам.** Скрытое поле-ловушка для ботов. Форму нельзя отправить быстрее 3 секунд. Не больше 5 заявок за 10 минут с одного адреса — в базе хранится только хеш адреса, записи удаляются через сутки.
- **Дубли.** У каждой отправки свой ключ, поэтому повтор не создаёт новую заявку. Тот же телефон и тот же повод за 10 минут тоже считаются дублем.
- **Панель.**
  - Каждый запрос к `/api/admin/*` проверяет вход в Supabase и наличие пользователя в таблице `admins`.
  - RLS запрещает анонимный доступ к таблицам.
  - Историю изменений нельзя ни править, ни удалить.

Тесты: `npm install`, затем `npm test`. Они проверяют сервер без настоящих Supabase и Telegram.
